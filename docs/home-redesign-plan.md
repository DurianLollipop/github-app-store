# TV 首页改造方案与边界

## 项目分析

- Kotlin + Jetpack Compose（Material3 与 TV Material3），未引入 WebView 或更换框架。
- `StoreRoot.kt` 维护目的地和详情路由，`PageTransition` 负责进退；`SaveableStateHolder` 保存各页面的搜索条件等状态。
- `StoreViewModel` 通过 StateFlow 提供目录、下载、安装、错误状态；目录来源是内置 / 签名远程快照与 GitHub Releases 缓存。本轮不调整数据协议和业务层。
- `Artwork.kt` 使用 Coil 共享 ImageLoader、OkHttp 和 SVG 解码器显示 README 提取的图标；缺失图片以明确的字母占位回退。
- 原首页采用 82dp 左侧栏、216dp 宣传横幅和横向信息卡片。问题是空间集中在横幅，图标较小、信息密度偏高；真实 Logo 还叠加了品牌色底，焦点只有约 1.025 倍缩放。

## 参考图的落地方式

保留参考图的三个层次：顶部居中玻璃胶囊、左侧标题与右侧丝绸流光、下部规则图标网格。保持 Orbit 品牌和真实目录，不复刻参考图中的第三方服务数据。

标准电视逻辑宽度约 960dp 时采用六列，左右安全边距 44dp；顶部导航高 86dp，标题区高 144dp，应用卡片约 122×87dp（1.4:1 横向圆角），名称 13sp。较窄逻辑宽度采用四列，较矮视口缩短标题区。物理 1080p / 720p 结合系统密度使用 dp 布局。

配色使用 `#F7F8FC` 画布、`#202437` 正文、`#778198` 次要文字，蓝紫粉低饱和渐变只用于背景。应用卡片使用薄亮边、清透面反射与柔和外投影；移除厚倒角和内暗框，字母占位使用同色系渐变。真实图标放在中性容器中，正常 Logo 使用 Fit；README 中 Jellyfin 横幅资产保留中央符号，沿用原图的深色底色铺满卡片。

## 动效、焦点和性能

- 图标放大 1.08 倍、抬升 3dp，阻尼 0.86 / 刚度 560 的可中断弹簧；阴影、柔光及名称颜色约 180–210ms 变化。按下缩至 0.975 倍，点击不等待动画结束。
- 导航胶囊 220ms 滑动，文字 / 图标颜色 180ms 变化；导航确认后切页，向下进入当前首页网格。
- 方向键目标独立于动画完成状态，越界不绕行；虚拟列表未加载的目标先定位再交接焦点，后续输入取消过时任务。已加载目标立即接收焦点并由原生 BringIntoView 协调滚动。
- 首页 LazyGridState 与最后焦点 ID 留在根层，详情返回不刷新数据、不重建整个目录；目标尚未加载时先恢复其可见性。
- 背景使用烘焙连续曲面纹理与独立合成图层，18 秒往返位移循环，无逐帧路径拼接或流体着色器。离开首页停止循环；低内存设备静态呈现。纹理与提示词见[流光素材说明](silk-wallpaper-asset.md)。
- 导航背景在根坐标下采样同一张壁纸，API 31+ 对独立背景层做局部 18dp 模糊，叠加半透明染色、双层折射亮边和浅投影；前景文字保持清晰。API 26–30 和低内存设备回退至染色与亮边，不使用全屏模糊。
- 系统动画缩放为 0 时取消装饰循环、位移和缩放，保留静态焦点边缘、柔光及选中状态。图标继续复用 Coil 内存 / 磁盘缓存，不因聚焦重新请求。

## 修改与验证范围

- `HomeScreen.kt`：背景、顶部导航、首页网格与图标动效。
- `StoreRoot.kt`：沿用原路由，接入顶部导航、网格状态和返回焦点；适配搜索空状态可用空间。
- `Artwork.kt`、`Theme.kt`：图标原始色彩适配、基础色值。
- `StoreNavigationTest.kt`、`HomeGridTest.kt`：真实五应用路径、快速按键、六列多行滚动、屏幕下方焦点恢复。
- 原 `DetailReadingTest.kt` 继续验证介绍首中尾、超长段落、大字号和触摸滚动。

构建、Lint、原生交互测试与模拟器实际截图是交付证据。六列多行目录仅存在于测试夹具，生产目录仍为原有五款。实体电视 60FPS、GPU / 内存占用、输入延迟与低内存硬件表现必须另行实测，不能从模拟器通过推定。
