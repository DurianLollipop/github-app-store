# Orbit 工具化迭代需求

日期：2026-11-11

状态：已进入 v0.3.0-dev 功能开发与验证。本文是需求与验收标准，不能仅据此认定全部验收完成；实际范围见[开发验证记录](tool-iteration-validation.md)。

实现基线：v0.2.2-dev，包含全站搜索、版本菜单及并发续传改造。

首发平台：Android TV；后续平台只预留数据边界，本轮不开发。

## 1. 产品目标与约束

Orbit 定位为用户自主使用的 GitHub 应用发现、下载、安装与更新工具。维护者只处理软件缺陷、兼容性适配和新功能，不承担逐个应用收录、上架、版本审核或首页运营。

核心链路：GitHub 搜索 / 用户添加仓库 → 自动获取 README 与 Releases → 展示与选包 → 下载和本机检查 → 用户确认安装 → 关联仓库并检查更新。

- 无必需的业务服务端、运营后台、远程目录发布和维护者凭据。
- 默认免登录；不在 APK 中内置共享 GitHub Token，不建设账户系统。
- 不依赖固定五款应用或维护者人工批准，正常使用不需要修改目录文件、执行维护脚本或等待 Orbit 发版。
- 复用 Kotlin、Compose、ViewModel / StateFlow、现有下载和安装架构，不重做无关模块。
- 保留现有 Apple tvOS 视觉、遥控器焦点、减少动画、详情阅读和历史版本菜单。
- 不建立完整 GitHub 应用索引，不保证发现所有应用，不将热度或首次安装确认描述为安全认证。

## 2. 与当前实现的差异

| 领域 | 当前实现 | 迭代目标 |
| --- | --- | --- |
| 首页与分类 | 五个内置开发样本 | 自动发现的候选池、本地规则分类与排序 |
| 搜索 | 已支持 GitHub 全站仓库搜索 | 保留原始仓库搜索，补充仓库直达与安装闭环 |
| README / 图标 | 已支持在线解析和缓存 | 扩展到所有打开的仓库，完善失败回退与持久化；不打包第三方图标 |
| README 正文 | 当前提取部分介绍，“查看 README”跳转外部 | 应用内阅读 README 正文，轻量排版、长文滚动与在线图片 |
| 列表返回 | 现有逻辑倾向保留原滚动位置及卡片焦点 | 从详情返回来源列表时回到顶部，保留查询、分类和已加载数据 |
| 安装来源 | 依赖人工审核目录、预录包名与证书；未知项目跳转官方页面 | 下载后检查真实 APK，用户确认首次来源，本机保存仓库与包身份关联 |
| 下载完整性 | 安装链路要求预先存在 SHA-256 | 区分上游摘要与本机摘要，支持上游未提供摘要的正常状态 |
| 应用更新 | 主要围绕目录中应用 | 围绕用户订阅、安装和主动关联的仓库 |
| 内容维护 | Python 脚本、审核记录和可选签名目录 | 日常使用无需上述流程；旧工具可保留作开发辅助 |

原始状态及历史验证见 [implementation-status.md](implementation-status.md)。原开发计划中人工收录、真机认证后上架、固定目录数量、远程签名目录运营等要求，由本文的新产品方向替代；历史事实保留。

## 3. 用户流程

1. 首次启动直接使用首页和搜索，不要求账号或配置服务器。
2. 首页展示自动发现结果、获取时间和推荐依据；用户也可直接搜索或输入仓库地址。
3. 进入任意仓库详情，获取介绍、在线图标、截图和 Releases；默认选择最新稳定版，历史版本默认折叠。
4. 有独立 APK 时展示候选，初步匹配设备；无 APK 时解释原因并保留官方发布入口。
5. 下载后检查真实包信息，首次展示仓库、包名、版本、证书指纹与检查结果，用户确认后交给系统安装器。
6. 以系统安装结果确认成功，再保存关联；已安装且用户主动关联的应用，也可纳入管理。
7. 后续只检查用户订阅或关联的仓库，发现新版本后提醒；下载与安装仍由用户发起。
8. 详情内可直接阅读 README 正文；退出 README 回到详情原入口，从详情返回来源列表则回到列表顶部。

## 4. 迭代一：任意仓库的下载与安装闭环（P0）

### T01 仓库直达与持久化

- 搜索支持关键词，并识别 `owner/repo` 与 `https://github.com/owner/repo`；明确仓库输入直接打开，不强制走模糊搜索。
- 校验地址，拒绝非 GitHub 仓库地址；仓库不存在、私有或无法访问时显示原因，不回退伪造结果。
- 采用 GitHub repository ID 标识仓库，保留当前 owner/name。改名或转移后，以 API 身份核对更新路径；无法核对时保留记录并提示，不能仅靠同名接管关联。
- 已打开仓库的资料、版本及来源持久化，退出进程后可查看最近成功的数据和获取时间。

### T02 自动展示与选包

- 展示资料按 README → 仓库简介回退；图标优先使用识别到的项目图标，其次作者头像，再到字母占位，标明作者头像不代表项目图标。
- README 只作为展示数据，不用于生成包名、签名信任或安全认证；不执行 HTML、脚本和上游代码。
- 图标、截图在线加载并采用容量受控的设备缓存；网络失败保留可用缓存，不要求完整离线图片库。
- 默认最新稳定版；只有预发布时明确标记，历史版本与额外包变体折叠菜单选择。
- 文件名只做初筛，真实 APK 的包名、versionCode、minSdk、ABI 和证书检查决定安装条件。
- 多个同级包、不同渠道或不同应用不能静默任选；显示文件名和已知差异，让用户选择。
- 一个仓库可发布多个应用或渠道；关联粒度为“仓库 ID + 包名 + 用户选择的渠道规则”，不能假设仓库与应用一一对应。
- 无独立 APK 时仍可浏览与订阅，说明当前不支持的资产类型；不把源码压缩包当安装包。

### T03 首次安装与完整性状态

- 移除普通仓库必须存在于审核目录的安装前提，保留现有来源地址约束、系统授权及 PackageInstaller 用户确认。
- 首次下载前展示仓库和 Release 来源。下载完成后，实际解析 APK，再展示包名、版本、证书指纹及兼容性检查；首次确认针对具体包身份，不是信任仓库内所有资产。
- 系统报告安装成功且包身份复核通过后，记录该仓库与包的关联；用户取消、安装失败不得标记为已安装。
- 上游提供 SHA-256：必须验证一致；不一致阻止安装并清理不可用文件。
- 上游未提供摘要：允许下载，计算本机 SHA-256 用于文件身份和后续复核，明确显示“上游未提供摘要”，不能声称完成上游摘要比对。
- 缺少上游摘要时，续传依赖资产 ID、URL、大小及可用的强验证器。缺少可靠续传身份或资源变化时重新下载，不把下载后计算的本机哈希当成预期哈希。
- 无有效 APK 签名、已知系统 / ABI 不兼容、损坏或不支持的安装格式应阻止提交并说明原因。
- 既有包更新必须核对已安装包的签名连续性；无法可靠判断的证书轮换不自动放行。不能通过重新确认来源绕过冲突，也不提供自动卸载重装。
- 下载行为和用户确认不构成“无恶意”“官方审核”保证，界面只展示实际核验结果。

### 迭代一验收

- 使用测试夹具中不在原五款目录的仓库，完成搜索 / 地址直达、详情、APK 下载、检查、首次确认、系统安装和重启后关联恢复。
- 覆盖有 / 无上游摘要、摘要错误、无 APK、多 APK、多包名、失败、取消和安装权限未开启。
- 未知仓库不再一律只允许跳转；不可安装情况仍能访问官方发布页。
- 原四路下载、断线续传、进程恢复和 Range 不支持时的降级保持有效，覆盖无上游摘要的恢复路径。

### T10 用户协议与风险告知（P0，随迭代一交付）

- 第三方项目安全风险、用户自主选择安装、第三方软件责任范围写入[用户协议草案](user-agreement.md)，不建立维护者逐个项目安全审核流程。
- 首次启用第三方下载 / 安装前，显著展示风险摘要、责任限制和完整协议入口，用户主动同意后继续；无预勾选、不默认同意，方向键和确认键均可操作。
- 拒绝后不下载、不安装，允许阅读协议和退出；确认保存协议版本与时间，仅存本机，重大条款变化重新提示。此记录不等同法律有效性保证。
- 设置提供永久可访问的协议入口，正文可遥控器滚动；日常下载不反复弹出完整免责说明，继续展示具体仓库来源和实际检查结果。
- “用户自担第三方项目风险”不取消基础完整性、包身份、系统兼容和签名检查，也不绕过系统安装确认；不使用“任何情况概不负责”的绝对免责表述，保留法律不能免除的责任。
- 验收覆盖首次同意 / 拒绝、重启保留、协议升级重新同意、全文阅读、返回焦点，以及未同意不得启动第三方下载或安装。应用内只展示协议正文，不展示文档维护说明。

### T11 应用内 README 阅读（P0，随迭代一交付）

目标：用户无需离开 Orbit 即可阅读项目 README，不能仅以简介提取或外部浏览器跳转视为完成；保留“在 GitHub 查看原文”作为补充入口。

内容与交互：

- 首次默认获取仓库默认分支的 README，展示正文、来源和最近成功获取时间；仓库实际存在其他语言 README 时，提供应用内语言切换，不只依赖正文中的语言链接，不进行自动翻译。
- 必须支持标题、段落、粗体 / 斜体、分隔线、有序 / 无序列表、引用、链接、行内代码、代码块、常见表格和图片。表格 / 代码不得挤出页面，宽内容支持遥控器横向阅读；上下键仍能退出该块继续阅读，不形成焦点陷阱。
- 常见 HTML `img` / `picture` 的图片与说明、`details/summary` 的折叠内容需有可读呈现；复杂 HTML、Mermaid、公式和视频不要求完整重现，但保留可读文本、源码或明确的原文入口，不丢失整篇正文。
- README 图片、仓库内相对文档链接和页内锚点根据实际仓库、分支及文件路径解析；文档锚点在阅读器内定位，其他仓库内 Markdown 可复用同一阅读器，外部链接明确跳转。
- 正文支持上下滚动、遥控器逐块阅读、大字号与触摸；长段落分块，目录锚点和可点击链接可聚焦，图片按比例显示并可打开预览。
- 进入 README 从正文顶部开始；关闭图片预览或退出子文档时恢复上层阅读位置与入口焦点。退出 README 返回详情时保留详情原位置，不套用 T12 的列表回顶规则。
- README 缺失、限流或失败单独展示，不影响已取得的版本与下载操作；有缓存时优先显示缓存并标注时间，没有缓存时提供重试和原文入口。

多语言 README 切换：

- 优先从当前 README 的语言导航链接，以及根目录、当前文档目录中的常见语言文件命名发现候选，例如 `README.zh-CN.md`、`README_zh.md`、`README.en.md`；其他目录通过 README 中的实际链接按需发现，不递归扫描整个仓库，不保证穷举所有语言文件。
- 只将同一仓库内、已确认存在且可作为 README 语言版本的文件列为可选项。普通安装说明、任意 Markdown 文件和外部翻译站点不能自动当成语言版本；跨仓库链接保留为普通链接。
- 至少发现两个有效版本时显示“README 语言”菜单，展示语言名称与实际文件路径；语言无法可靠识别时显示原文件名，不按猜测误标。只有默认 README 时不显示无效语言菜单；默认文件未声明语言时标为“仓库默认”，不一律当作英文。
- 选择后在应用内加载该语言的真实正文，当前来源、图片、相对链接及锚点按所选文件路径解析；README 语言不会改变应用版本、APK 选择或安装来源。
- 按仓库 ID 在本机记住用户主动选择的文件，下次进入该仓库优先使用；未选择时保持仓库默认。成功切换后正文从顶部开始，焦点落在可见阅读入口；关闭语言菜单但未选择时保留原阅读位置。
- 切换失败时保留原正文和原选中项并提供重试；语言文件确认删除后提示并回退默认 README。限流或临时网络错误不能据此断言语言文件不存在，不清除有效缓存和偏好。
- 发现结果和正文分别缓存，复用 T08 的并发、冷却与请求调度；只加载用户选择的语言正文，不预取所有语言全文，不为每种语言打包素材或增加翻译 SDK。

实现与性能边界：

- 可自研或采用现成 Markdown 解析 / 渲染组件，优先复用 Compose、现有网络和 Coil 缓存；不得为阅读功能更换技术栈或引入完整浏览器 / 前端应用运行时。轻量原生方案优先，其他方案只有在证明体积与实机表现符合约束时采用。
- 组件选型比较必要语法支持、依赖树、许可证、构建体积和长文表现；不为少数特效引入重型语法高亮、图表、公式或视频 SDK。自研同样须覆盖必要语法，不用低质量正则替代完整块级解析。
- 正文按需请求，解析和图片处理不阻塞主线程；正文解析结果按“仓库 ID + 分支 / ref + 文件路径 + 内容标识”复用，语言文件互不覆盖。焦点、按键和动画不得触发整篇重复解析。
- 长文分块懒渲染，图片按可见区域加载、按显示尺寸解码，不一次性创建全部文本节点和加载全部原图；阅读器资源在离开后按缓存策略释放。
- 起步保护上限：单篇解码后的 UTF-8 正文 1 MiB。超限、超深嵌套或异常结构应有明确提示和原文入口，不静默截断，也不导致 OOM 或应用崩溃。该上限是待验证的实现参数。
- 选型初始体积预算：同一构建类型、ABI 与压缩设置下，阅读功能引入的 APK 净增目标不超过 2 MiB；交付时报告实际值及主要依赖。不要为了达标移除现有功能或降低正文可读性；超预算应先精简方案再确定取舍。

验收：

- 通过中英文、图片相对路径、引用式链接、SVG、表格、长代码、折叠段落、页内锚点、缺失 README、限流和离线缓存样例；展示正文超出原简介提取长度的后半部分与结尾，证明不是仍显示摘要。
- 多语言验收覆盖默认文件加中文 / 英文等不同文件、非标准目录中的实际语言链接、只有单一版本、普通文档误识别排除、文件删除、临时失败、缓存与重启记忆；遥控器可以打开菜单并切换，来源和相对图片随文件正确变化，未选语言正文不发生预取。
- 以固定的约 100 KiB 长文和 30 张图片链接夹具验证，图片仅按视口懒加载；连续方向键与文字缩放不重做全篇解析，正文首中尾均可用遥控器到达。
- 同设备、同构建类型记录接入前后的 APK 大小、详情首屏、正文首屏耗时、峰值内存和滚动表现；在 I4 真实 TV 矩阵复核。缓存正文首屏目标不超过 500ms，常规列表 / 详情不得因正文预加载等待网络或解析；目标未达成须记录原因并优化，不能只以模拟器截图验收。

### T12 列表返回顶部与焦点协调（P0，随迭代一交付）

- 按本次新增要求，覆盖原先“从详情返回后恢复列表原卡片及滚动”的方案：首页、搜索结果、分类、收藏 / 订阅和已安装列表，点击条目进入详情后，返回来源列表时滚动到顶部（偏移为 0）。后续新增列表沿用该规则。
- 返回只重置滚动和焦点，不清空搜索词、分类条件、已加载分页、排序及数据缓存，不再次请求第一页；列表回顶不代表刷新或重新排序。
- 回顶后将焦点放在当前结果的第一张可见卡片；没有结果时放到可见的搜索 / 筛选 / 重试入口。不能恢复到屏幕外的旧条目，也不能让自动聚焦再次把页面拉回中段。
- 导航转场开始时协调列表回顶与首项布局，列表可交互前确定目标；不展示旧中段再闪到顶部，不排队播放长距离滚动动画，不阻塞后续按键，减少动画模式即时完成。
- 只在“详情返回来源列表”触发；列表内关闭版本菜单、弹层、截图预览或进行局部操作不回顶；README / 子文档的返回按 T11 保留上层阅读位置。
- 列表正在加载或数据变化时，在有效结果布局后设置一次焦点；无数据则停在明确入口，不无限请求焦点。离场页不得抢焦点或响应按键。
- 验收分别从首页、搜索、分类的第二屏及更后位置打开详情，再通过遥控器返回和界面返回按钮退出，检查首项偏移为 0、焦点可见、查询 / 分类 / 分页保留且无额外刷新；收藏 / 订阅及已安装列表在 I2 同步覆盖。
- 快速重复进入 / 返回、空列表、结果变少和 720p / 1080p 均不得崩溃或跳错页；原来断言“返回旧位置”的测试须按新规则调整，不能以旧测试全部通过替代新需求验证。

## 5. 迭代二：用户自己的应用管理（P0，依赖迭代一）

### T04 收藏、订阅与已安装关联

- 收藏：加入本地快速访问，不自动加入周期版本检查。
- 订阅：加入版本检查，默认关注稳定版，用户可切换预发布渠道。
- 从 Orbit 安装成功的应用默认纳入更新检查，并允许用户关闭；不额外自动收藏。
- 显式订阅与安装自动检查分别保存启用状态，仓库请求去重。取消其中一项不关闭另一项；两项均关闭才停止该包的检查。仓库级订阅关注新发布，包级安装检查使用该包选定渠道，渠道不同则分别判断，不相互覆盖。
- 外部安装的应用允许用户主动选择仓库并关联；以下载后真实 APK 或已记录的可靠包信息核对，不能凭相似名称自动绑定。
- 一对多仓库、渠道切换须显示对应包名并显式选择；删除收藏、取消订阅、解除关联与卸载是不同操作。
- 卸载不会自动抹掉收藏与显式订阅；仅因安装而纳入的自动检查在确认卸载后停止。
- 仅处理系统允许读取的应用信息；无法识别时解释限制，不要求全设备扫描或仅为此扩大包可见权限。

### T05 更新检查与比较

- 周期任务和手动检查只覆盖订阅、有效安装关联及 Orbit 自身更新，不扫描首页全部候选。
- 复用现有约 6 小时调度意图，受系统任务限制；手动刷新同样遵守限流，展示最后成功检查时间。
- Release 有变化只能标为“发现新发布”；不能只比较 tag 或发布日期就断言可升级。
- 已知匹配包名、签名且 versionCode 更高时标记“可更新”；信息不足显示“新发布待检查”，用户下载检查后再确认安装资格。
- 支持忽略某版本、恢复提醒、检查失败重试；不自动下载、不静默安装。
- 资源撤回、仓库不可访问或签名冲突时保留上次数据与失败说明，不自动转向第三方镜像。
- 历史版本可下载，但不承诺系统允许覆盖降级。

### 迭代二验收

- 收藏 / 订阅 / 关联重启后保留；取消显式订阅停止其触发的检查，安装自动检查仍启用时继续；两者都关闭后停止，解除关联不卸载应用。
- 不订阅且未关联的首页和搜索结果不进入周期检查队列。
- 测试同签名升级、同版、降级、异签名、同仓库不同包、外部安装关联及卸载后的行为。
- 没有真实 versionCode 时，不出现确定的“可更新”；网络失败不抹掉本地管理记录。

## 6. 迭代三：自动首页发现与本地推荐（P1，依赖前两轮）

### T06 有边界的自动候选池

- 本节应用资格及平台筛选用于默认应用发现、当前平台热门与最近发布；独立的“GitHub 热门项目”入口采用 T14 的跨平台项目范围，不受必须有 APK 的限制。
- 通过少量内置查询规则发现 Android / Android TV 相关公开仓库，规则是程序默认值，不是逐个维护的应用名单。
- 全站搜索保留原始仓库搜索；首页则逐步检查 Releases，优先纳入确实存在独立 APK 的候选。不能把搜索命中数当可安装应用数。
- 未完成资产检查的项目可放在独立的“相关项目”区域，标注“安装包未检查”；不混入已发现 APK 的列表。
- 候选按仓库 ID 去重；同一应用的不同 Release 不生成多张首页卡片。
- README 获取按可见项 / 详情懒加载，不为整个候选池同时获取全部截图，不为推荐排名自动下载 APK。
- 查询页上限、候选数量、详情补全数量与缓存容量均须受控；触达 API 限制后停止并保留已有结果，不抓取无限列表。
- 无可用候选时提供搜索和添加仓库入口；固定五款不作为伪装成实时推荐的保底结果。

### T13 当前平台的热门应用推荐（P1，随迭代三交付）

目标：首页自动发现与当前平台相关、近期 Star 增长较快的应用，无需维护者建立热门名单；平台相关性和应用资格先于全站热度。热门默认指所选时间段新增 Star 较多，不是累计 Star 总量较大。

平台与候选：

- Android TV 首版默认使用 Android TV 平台画像，优先发现作者标记或说明支持电视的应用；普通 Android 应用单独标注“TV 兼容性未知”，不因有 APK 就混充 TV 适配应用。
- 通过平台 topics、名称 / 说明 / README 关键词进行少量独立查询再合并，不用 Kotlin、Java 等编程语言作为平台依据。例：`topic:android-tv archived:false` 用于电视主题候选，`android-tv in:readme archived:false` 用于补充发现；关键词命中只是线索，还需按 T06 检查实际发布资产和应用用途。
- 过滤无安装包、仅 SDK / 组件库 / 教程 / 资源合集等非应用项目；不能确定时进入“相关项目”或展示未知状态，不伪装成可安装热门应用。非独立 APK 项目仍可在全站搜索中找到。
- 后续 Android 手机、桌面各平台复用“平台画像 + 资产格式 + 兼容性证据”的机制，分别建立候选；本轮不增加尚未实现平台的客户端或假安装入口。

展示与热度：

| 首页入口 / 筛选 | 规则 | 说明 |
| --- | --- | --- |
| 为你发现（默认） | 使用 T07 综合评分 | 平台相关、资料、维护、本地兴趣及适度热度共同决定 |
| 本平台热门 | 先通过应用资格与平台过滤，再按所选时段新增 Star 排序；可切换总 Star 排序 | 展示时段新增数、总量、来源、获取时间与平台依据 |
| GitHub 热门项目 | 不限平台和安装包类型，默认按 T14 的近期 Star 增量排序，也可按总 Star 排序 | 可包含桌面应用、命令行工具、框架和资料项目，不代表当前设备可安装 |
| 最近发布 | 在同平台合格候选中按有效 Release 发布时间排序 | 不把仓库的 `updated_at` 当软件发布时间，不把新发布等同热度上涨 |

- 可采用首页分区或轻量筛选呈现，保持现有六列布局；默认推荐、本平台热门和最近发布复用平台候选池，GitHub 热门项目使用独立查询范围，共享仓库资料、缓存和网络调度，不扫描或下载完整仓库数据。
- 本平台候选合并平台查询与近期趋势候选，再按共同时间口径的增长数据排序；不能只取总 Star 最高的一批仓库充当近期热门候选。只表示已发现并取得有效增长数据的候选，不保证完整全站排名。
- 不把 Star 总量、最近提交或最近 Release 描述为近期涨星。增长数据及排序规则统一遵循 T14；不为生成榜单引入自营持续采集后台，也不全量遍历 stargazer 用户列表。
- 稳定成熟应用不因近期无提交就直接淘汰；不相关项目即使 Star 更高也不能越过平台 / 应用资格过滤。相同作者与项目多版本依旧去重，并遵守用户隐藏、已安装排除规则。
- 本平台热门中个人偏好不覆盖用户所选的“近期增量 / 总 Star”排序含义；综合个性化仍在“为你发现”中体现，页面明确区分两者。
- 继续遵守 T08 的 12 次首页 API 请求预算、2 路并发、缓存与退避；首次预算内只能确认少量应用时如实展示，不为填满网格突破预算。首页返回规则仍为 T12，不因返回重算热门排序。

验收：

- 混合电视应用、普通 Android 应用、桌面应用、高 Star SDK、无 APK 仓库、重复作者及用户隐藏项目，验证“平台 / 应用资格过滤 → 所选时段增长排序”，高 Star 无关项目不得占据电视热门列表。
- 验证热门、最近发布、默认推荐的依据不同且可解释，显示实际 Star 和获取时间，无证据时不展示涨幅；同平台候选不足有明确空状态。
- 各入口复用资料请求与缓存；离线或限流不清空已有结果，不新增服务端、维护者名单或新的安装授权规则。

接口能力参考：[GitHub 仓库搜索条件](https://docs.github.com/en/search-github/searching-on-github/searching-for-repositories)、[GitHub 仓库搜索 CLI 参数（含 Star 排序）](https://cli.github.com/manual/gh_search_repos)、[GitHub Search API 与限流说明](https://docs.github.com/en/rest/search/search)。搜索能力支持候选发现，不提供应用真实性或兼容性认证。

### T14 与平台无关的 GitHub 热门项目入口（P1，随迭代三交付）

- 首页增加独立“GitHub 热门项目”入口，与“本平台热门”明确区分。查询不加入 Android TV、操作系统、编程语言或必须存在 APK 的限制，允许应用、命令行工具、框架 / 组件库、教程与资料项目出现。
- 自动发现近期增长快的公开项目，不维护固定名单；候选须包含近期趋势来源，不能仅从高 Star 仓库抽取。默认排除归档和 Fork 重复结果，按仓库 ID 去重，不宣称完整全站榜单。
- 默认排序为“近期 Star 增量”，时间选项提供“今日 / 本周 / 本月”，初始选中“本周”。新增数相同按总 Star、仓库 ID 确定同分顺序；“增长快”首版按同一时段的新增数量衡量，不默认按百分比排序，以免极小基数主导榜单。
- 另提供“总 Star”排序，不受近期增长影响；选中时隐藏或禁用与它无关的时段控件，并清楚显示排序名称。切换回近期增量恢复上次时段，排序与时段按入口在本机记忆。
- 卡片展示仓库名、作者、简介、当前排序指标及获取时间。增长模式突出“本周新增 Star”等指标，总 Star 独立展示；平台 / 类型有依据才标注，许可证不明不得一律称开源。点击复用详情、多语言 README、收藏与订阅能力。
- 不因进入该入口而更改设备平台。只有存在当前支持的独立 APK 且满足 T02 / T03 时才提供本机下载与安装；桌面资产、框架或无安装包项目保留版本浏览与官方入口，不展示虚假 Android TV 安装按钮，不自动下载其他平台文件。
- 不套用 T07 的 TV / 开源应用资格或本地兴趣加权，严格按用户所选指标排序；用户隐藏仍生效，已安装状态不自动隐藏项目。增长榜不额外打散成与指标相反的顺序；综合推荐的多样性安排留在“为你发现”。
- 首次进入或缓存过期后按需查询，未打开入口不预取所有时段、分页、README 和媒体；查询键包含候选范围、排序方式、时间口径与数据源。共享仓库缓存、T08 总预算 / 容量 / 并发与退避，不给每个入口重复分配一份额度。
- 从详情返回本入口按 T12 回顶，保留已加载分页和入口选择，不切回本平台热门，也不重新查询第一页。

增长数据获取与口径：

- 实施前验证当前官方 Star 历史聚合接口的实际匿名可用性、日 / 周边界及响应；当前文档提供 `GET /repos/{owner}/{repo}/stargazers/history`。对有限候选按需取得聚合增长，不获取全量点赞用户，不要求用户等待本机先积累一个月数据。
- 跨平台近期候选优先评估直接读取 GitHub Trending 的 Today / This week / This month 列表及其公布新增数；使用轻量 HTML 解析器和独立可替换适配器，不引入浏览器运行时。页面不是稳定 API，接入前须验证访问条件、解析与源站使用要求，不能把该方案写成已稳定运行。
- 历史接口与 Trending 的时间边界不应擅自当成精确滚动 24 小时 / 7×24 小时 / 30×24 小时。界面显示实际来源与统计时段；不同日界、截止时间或指标口径未能统一的数据不可混算排名。数据源期间值的重新排序属于 Orbit 的排序，不冒称源站原榜序。
- 官方日聚合按所选日历期间求和，表达期间新增 Star；总量快照相减只能表达观察区间的净变化，不能混称同一新增指标。返回零、缺失、权限不足、超时和格式变化必须区分，不能将未知增长当作 0。
- 默认“近期增量”为绝对新增数，非增长率；首版不增加涨幅百分比模式。如后续增加，需同时展示基数、绝对增量及防小基数放大规则。
- 首次运行可读取已发布的期间数据。真实来源无可用增长数据时显示“近期增长暂不可用”、最后成功缓存及重试 / 官方趋势入口；“总 Star”始终作为可选模式，不能无提示拿总量替代增长榜。
- 增长补全与趋势请求纳入统一预算，分批为候选补全；数据不足时少展示并说明候选范围，不为追求全站精确榜单突破预算。实现不新增自营数据服务，数据源失效仅需按 Bug / 上游变更维护适配器。

验收：

- 固定样例 A 总量 100,000 / 本周新增 20，B 总量 2,000 / 新增 800：默认本周增长榜 B 在 A 前，总 Star 模式 A 在 B 前；其他期间的顺序随对应真实增量变化。
- 覆盖今日 / 周 / 月切换、同分、跨周月边界、时段不一致、缺失与真实零值、源站格式变化、限流及离线缓存；增长缺失不会触发静默总量替换，指标名称和数据时间一致。
- 验证电视 / 桌面应用、命令行项目、SDK 和无 APK 仓库跨平台均可浏览，平台热门则先做资格筛选；保留 README 语言切换、收藏 / 订阅、安装边界与返回回顶回归。

2026-11-11 核对依据：[官方 Star 历史聚合文档](https://docs.github.com/en/rest/activity/starring#get-repository-star-history)、[GitHub Trending 本周页面](https://github.com/trending?since=weekly)。已核对公开文档和页面；尚未完成客户端匿名接口实测或解析器验证，开发时须落实，不代表现有 Orbit 已具备增长数据。

### T07 可解释的本地排序

本节综合评分用于“为你发现”；平台应用资格也适用于 T13 的本平台应用列表。T14 的跨平台热门项目使用近期增量 / 总 Star 两种明确排序，不套用 TV 应用资格。

推荐顺序：资格过滤 → 多来源候选合并 → 本机评分 → 去重与多样性 → 稳定展示。

资格条件与证据：

- 已发现独立 APK、仓库状态、已知系统要求用于过滤；实际 ABI / SDK 信息不足时标为未知，不假定兼容。
- 作者声明 TV 支持、APK 中的 TV 入口信息、本机使用记录分别保存证据来源；均不得伪造为维护者真机认证。
- 无开源许可证的公开仓库可在全站搜索中显示；不进入以“开源应用”为名的默认推荐池，详情显示许可证未知。许可证自动识别也不是合规审核结论。
- 已归档项目默认不进入新发现列表，但用户已有订阅保留，并展示归档状态。

第一版评分建议如下，属于待验证默认参数，不是效果承诺：

| 因子 | 初始权重 | 规则 |
| --- | --- | --- |
| TV 相关证据 | 30% | 作者明确声明优于仅关键词命中；未知明确标注 |
| 应用与发布资料完整度 | 25% | 有 APK、可识别介绍和来源；不把资料齐全等同安全 |
| 维护与发布情况 | 20% | 结合最近有效发布与归档状态，避免按提交频次奖励刷量 |
| 本地兴趣 | 15% | 收藏、主动订阅、明确访问优于单次曝光 |
| 热度与探索 | 10% | 有可靠数据时参考近期 Star 增量，总 Star 只作压缩后的辅助信号；增长未知不编造成零，给低曝光项目保留机会 |

- 各因子归一化；缺失值按中性处理且保留置信信息，不编造数据。新用户兴趣分统一中性。
- I3 开发前固定首版各因子的输入、归一化公式、阈值、探索轮换周期与同分排序（最终按仓库 ID），记录为版本化规则及确定性样例。验收检查规则执行，不把推荐转化效果当成未经验证的承诺。
- 每行六张最多两张相同规则分类、同作者最多一张；候选不足时可以放宽多样性约束，不降低基础资格。
- 显示“与电视相关”“与你收藏的工具相似”“最近发布”等可核对理由，不显示无依据的“安全精选”。
- 支持“不感兴趣”、恢复隐藏及重置本地偏好；隐藏优先于评分。
- 默认新发现列表排除已确认安装项；用户管理区继续保留入口。
- 页面停留时不因后台评分刷新而换位；仅主动刷新或新一次首页会话应用新顺序。从详情返回仍视为同一会话，保留数据顺序，按 T12 回到顶部并将焦点置于首项。
- 分类通过 topics、说明关键词和包信息规则生成；无法归类进入“其他”，不是沿用仓库编程语言充当产品分类。

### T08 缓存、请求预算与降级

- 首页读取本地缓存立即展示，再按有效期渐进刷新；详情、搜索、更新检查复用请求去重与数据缓存。
- 起步预算：一次首页刷新最多 12 次 GitHub API 请求、最多 2 个并行 API 请求，含查询分页和资产补全；图像另设有限并发。预算是上限，不是必须耗尽的配额。
- 首页候选默认 24 小时有效，用户管理的版本检查独立调度；连续手动刷新不能绕过冷却和限流。
- 趋势入口数据单独按“范围 + 排序 + 时段 + 数据源”缓存，初始有效期设 6 小时；日 / 周 / 月切换边界到达时失效，离线缓存仍展示原统计期间和时间，不能将昨日缓存改标为今日数据。依旧受统一预算与退避限制。
- 候选池上限先设 200 个仓库；跨刷新渐进补全。达到上限后按时间和使用情况淘汰，收藏、订阅、关联数据不随候选淘汰。
- 限流按响应信息退避；额度不足优先用户当前搜索 / 详情，暂停首页预取，更新检查错峰；不硬编码固定“永远可用额度”。
- 网络错误保留有效快照与时间，首次无缓存则显示可操作空状态；不白屏、不循环立即重试。
- README / Releases 解析失败相互隔离；保留上次成功字段，展示资料失败不能清空有效版本。

### 迭代三验收

- 使用超过五个仓库、不同分类、同作者及无 APK 的确定性数据，验证候选资格、权重、去重、多样性与隐藏优先级。
- 网络请求计数测试证明预算和并发上限生效；连续刷新、限流及退出页面不造成请求风暴。
- 冷启动缓存命中、无网、无结果、部分字段失败、候选不足均有对应展示。
- 同一可用快照和本地偏好产生稳定结果，停留期间不重排；从详情返回保留列表结果与顺序，按 T12 回顶且不重复加载。
- 推荐中的未知兼容性、头像回退和许可证未知等状态不被误写为已验证结论。
- T13 的平台热门、最近发布与默认推荐可区分；热门默认按近期增量并支持总 Star 排序，无关或非应用项目不能绕过平台应用资格过滤。
- T14 独立展示跨平台热门项目，不因无 APK 或不属于 Android 而被应用资格误删；不能安装的项目不出现误导安装操作，各入口请求总量仍在统一预算内。
- 近期增量榜满足 T14 的低总量高增长样例、时段与来源口径、缺失降级验收；不得用高 Star 总量榜替代。

## 7. 迭代四：迁移、工具设置与发行回归（P1，发布前完成）

### T09 数据迁移与工具设置

- 现有目录和快照不再承担任意仓库的安装授权；旧脚本和签名目录能力可保留作开发辅助，不作为正常运行依赖。
- 五个样本只保留必要的测试夹具或明确标注的示例，不继续作为首页生产数据源。
- 原有下载任务、安装关联、忽略版本和应用设置须有版本化迁移；旧记录缺字段进入“待重新检查”，不得直接获得新信任。
- 每轮启用新数据模型时必须先完成该轮必要迁移，I1 即覆盖旧任务与身份字段；不能将兼容工作推迟到 I4。I4 负责从既有开发版本升级的完整回归。
- 本机已安装应用的实际包身份是关联基础；旧审核证书可保留作来源记录，不替用户伪造新的确认行为。
- 安装和恢复任务不再依赖目录的 24 小时审核新鲜度，改为核对所选 Release 资产身份、当前文件及安装关系；删除或替换资产需要重新检查，离线安装只允许已完整检查且未发生可知变化的文件，并说明来源检查时间。
- 设置提供缓存清理、更新检查开关、减少动画、偏好重置及用户数据清除，分别说明影响；清缓存不删除订阅和包身份关联。
- 卸载 Orbit 会失去本地记录的边界应明确；不承诺云恢复。导入导出放入后续候选，不阻塞本轮。
- 更新 README 与使用说明，删除把日常收录 / 审核 / 签名目录部署当作用户前提的表述；历史实现记录保留时间和语境。

### 发行验收

- 升级旧数据后，可继续处理合法下载任务，损坏 / 不匹配记录可恢复或给出明确重试路径。
- 遥控器覆盖首页、搜索、分类、详情、首次确认、订阅、版本菜单、下载和返回；连续方向键、720p / 1080p、大字号和减少动画回归。
- README 正文首中尾、图片 / 宽表格 / 代码阅读、嵌套返回位置，以及详情返回各来源列表回顶按 T11 / T12 验证；记录阅读器体积与实机性能对比，不能由“有 README 链接”代替完成。
- 至少两种真实电视 / 盒子验证安装、升级、长下载、断网恢复、休眠与任务调度；报告设备型号和系统版本，模拟器结果不能替代真机结论。
- 保留并扩展已有单元测试、原生 UI 测试、构建及 Lint 检查；真实联网案例与确定性协议测试分开记录。

- 正式签名与 Orbit 自更新另行完成发行验证，这是软件发行维护，不是内容运营。

## 9. 本轮不做与完成定义

不做运营后台、人工上架系统、维护者版本审批、共享 Token 服务、安装包镜像、云账户同步、完整全站索引、模型训练、行为上传、静默安装、Split APK / XAPK / AAB 支持以及其他平台客户端。个人 GitHub 授权可作为后续增强，保留匿名使用入口，不强制登录；匿名请求仍受网络和 GitHub 额度限制。

本轮完成必须同时满足：

1. 维护者不修改目录、不逐个批准版本、不发布远程快照，用户仍可发现、添加和管理新的仓库。
2. 任意满足条件的公开仓库可走完整本机下载与安装链路，校验依据与未知信息明确。
3. 新版本由用户自己的订阅与安装关联驱动，更新不会绕过包身份核对和系统确认。
4. 首页数据来自自动发现与本地偏好，平台和独立跨平台热门默认按真实近期 Star 增量，提供今日 / 本周 / 本月及总 Star 排序，支持最近发布，不再固定为五个开发样本；异常时仍可搜索与访问用户记录。
5. 不依赖 Orbit 自有业务服务器；用户网络仍需访问 GitHub、发布资产和图片原始地址，不能承诺所有网络都畅通。
6. 交付文档明确每项已实现、受控测试通过和真实设备验证的范围；没有验证的性能与兼容性不写成事实。
7. 第三方软件风险与责任边界写入用户协议并在应用中显著告知，用户主动同意；该约定不被当作移除基础技术检查或免除法定责任的依据。
8. 应用内能阅读 README 正文而非仅摘要或外部链接；仓库实际提供多语言 README 时可切换并记住选择，不自动翻译。必要 Markdown 格式可读，依赖体积、懒加载和长文性能按 T11 交付验证记录。
9. 详情返回来源列表按 T12 回到顶部并保持焦点可见，保留筛选与已加载结果，不触发整页重新获取。

维护者后续工作限定为程序 Bug、上游接口 / 格式变化适配、系统兼容、功能和软件发行；用户对自己的仓库选择与首次安装作决定。无需日常内容运营不代表软件永远不需维护。
