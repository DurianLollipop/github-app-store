## 已验证的环境与规则

- JDK 17、Gradle 8.11.1、AGP 8.9.2、Kotlin 2.1.20、Android SDK / Build Tools 35。
- Android TV API 33 ARM64 模拟器，1920×1080；不是实体电视测试结果。
- 单元测试覆盖选包歧义、SDK / ABI 过滤、versionCode 比较、签名冲突、下载损坏、缺少摘要、上游 404、目录签名篡改及防回退。
- 原生导航测试覆盖详情与返回、方向键进入内容区、搜索筛选与无结果、下载中心空状态。
- 实际官方 APK 检查发现 Android 13 的归档解析器仅在同时提供 `GET_SIGNATURES` 时收集证书；已兼容处理，API 28+ 仍读取当前 `SigningInfo.apkContentsSigners`，不改为信任旧证书。[Android 13 官方源码](https://android.googlesource.com/platform/frameworks/base/+/refs/tags/android-13.0.0_r1/core/java/android/content/pm/PackageManager.java)

## 与原计划的实施差异

1. **存储**：首轮使用原子 JSON 与本地偏好设置，避免在目录很小时引入额外数据库迁移；保持数据层接口，后续按规模迁移 Room / DataStore。
2. **下载调度**：当前采用带通知的前台 dataSync 服务，并处理长任务超时。UIDT 分支与 Range / ETag 续传仍待新增系统版本和网络矩阵验证。
3. **目录部署**：已实现可选签名远程目录的协议和客户端验证，但尚未部署托管地址、接入正式目录公钥或建立生产签名流程。
4. **发行基线**：先固定已完成构建验证的 API 35 组合；公开发行前应重新核对最新 targetSdk 要求并完成升级验证。
5. **应用数量**：目前 5 个开发样本、2 个有真实 APK 审核记录，未达到公开测试目标 20–30 个。
